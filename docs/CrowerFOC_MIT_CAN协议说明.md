# CrowerFOC MIT 布局 CAN 协议说明

## 当前实现

- CAN Classic，标准 11-bit ID，默认 1 Mbps、节点 ID=1；FDCAN1 使用 PB13/TX、PB12/RX。设备接收命令 ID `node_id`；收到该节点首个有效 8 字节帧后，以同一 ID 周期回传状态，周期约 1 ms。没有主控时固件不会持续发送空闲帧。本次已完成离线构建和协议/编解码测试；本机目前未枚举 CAN 适配器，尚未完成总线实测。
- 控制帧借用常见 MIT 运控的 8 字节位布局：`p[15:0] | v[11:0] | kp[11:0] | kd[11:0] | Iq_ff[11:0]`。本项目所有控制量和反馈量都使用电流，不定义扭矩、Nm 或电流到扭矩的换算。
- 字段范围：位置 ±12.5 rad，速度 ±30 rad/s，Kp 0..500 A/rad，Kd 0..5 A/(rad/s)，Iq 前馈 ±40 A。控制律为 `Iq_cmd = Kp*(p_ref-p) + Kd*(v_ref-v) + Iq_ff`，约 1 kHz 更新，最终请求受运行电流限制裁剪。
- MIT 来源仅用于帧的位布局；本项目自定义了其单位语义和反馈格式，因此这不是采用标准 MIT 扭矩语义的即插即用设备。控制位置不使用固定减速比。未启用输出轴编码器时，反馈使用电机轴编码器；启用并验证输出编码器后使用输出轴角度和速度。

## 控制帧

| 字节 | 字段 |
|---|---|
| 0..1 | p，16-bit unsigned |
| 2 | v[11:4] |
| 3 | v[3:0] 与 kp[11:8] |
| 4 | kp[7:0] |
| 5 | kd[11:4] |
| 6 | kd[3:0] 与 Iq_ff[11:8] |
| 7 | Iq_ff[7:0] |

量化公式为 `uint = round((x-min)*(2^bits-1)/(max-min))`；主机客户端将越界值饱和到协议边界。位置字段范围为 ±12.5 rad；连续旋转时主控应按反馈处理回绕，并持续更新位置目标。

## 特殊命令

CAN ID 为 `node_id`，数据前 7 字节为 `FF`，末字节操作码：`FC` 进入使能态、`FD` 退出并回到 IDLE、`FE` 在 IDLE 时设置本次运行的零点。使能要求校准有效、无故障，且电流、母线和温度条件通过；取得许可后首个有效运控帧可自动进入闭环。停止或故障后需要通过 USB 清故障并重新许可。命令超过 100 ms 未更新时，通信看门狗停止驱动并锁存故障。

## 状态回传

CAN ID 为 `node_id`，每帧 DLC=8：byte0 节点 ID；byte1..2 位置 16 位；byte3..4 速度 12 位；byte4 低半字节与 byte5 组成实测 Iq 12 位；byte6 温度偏移值（摄氏温度+40，`FF` 表示无传感器）；byte7 为故障状态（0 正常、非 0 有故障）。位置、速度和电流字段使用与控制帧相同的范围。

## 第二编码器与输出轴测量

第二只 TLE5012B 与电机编码器共用 SPI3_SCK / SPI3_DATA，独立片选为 PB6 (`SPI3_CS_ENC2`)。主板网表中 FPC1-2 接该片选、FPC1-3 接 DATA、FPC1-4 接 SCK、FPC1-1 接 VDD、FPC1-5/6/7 接地。固件每约1ms读取两只编码器；对各自角度展开后计算输出轴多圈角度和速度，并用两轴累计转角的比值在线估算传动比，不采用写死减速比。输出编码器未启用或读数异常时，速度/位置控制不允许启动。

## 验证状态与限制

Python codec 测试覆盖打包/解包、±40 A 边界和特殊命令；固件可构建。CAN 适配器回环、位时序、目标主控兼容性、节点冲突、命令超时及负载下控制尚未实测。第二编码器板此前未安装，需实际接入后验收角度、方向、速度与传动比；新的电流环扫频也需刷入本版本后实际运行确认。

MIT 位布局与特殊帧格式参照 [T-Motor AK 系列模组驱动说明](https://store.tmotor.com/images/file/20220307/1646621088818055.pdf) 第 35–38 页；此处仅参考字段打包方式，CrowerFOC 的字段语义为电流。
