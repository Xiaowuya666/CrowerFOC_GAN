# 编码器换相、电流环与调试计时器：实机调查结果

2026-10-09 13:52，空载电机、母线约23.07V。已按授权烧录、复位、校准和执行转动测试。**已修复并复现验证多个实际缺陷；没有足够历史同步数据将用户原先的一次过流唯一归因。当前测试不等于20A额定或40A峰值验收。**

## 最关键的确认缺陷：应用时钟依赖调试器

旧固件用DWT CYCCNT调度编码器、计算数据年龄、执行ADC超时和主机心跳超时，也用于WS2812忙等。当前安装的pyOCD在`CortexM.disconnect(resume=True)`中写DEMCR=0，关闭DWT计数。因此程序可以仍显示RUNNING，应用时钟却已经停止。

空闲时RGB在关中断后等待停止的计数器，会卡住中断，USB与SysTick假死；运行时RGB被禁用，编码器轮询仍可能停止，年龄检查和心跳超时也同时失效，FOC可能一直用旧角度。它是确实存在、足以破坏换相和保护的缺陷，不能当作USB插拔问题，也不能靠增加过速保护补救。由于缺少原过流前的同步角度/时钟轨迹，不能宣称这就是历史37A记录的唯一原因。

[旧固件空闲复现](fault_results/20261009_132910_swd.json)：关闭TRCENA期间DWT停止，编码器计数3443保持不变；SysTick仅先推进到2215，然后被RGB等待卡住。恢复DWT后才恢复。该早期文件的read_only=true是脚本元数据错误，此测试实际修改过DEMCR；脚本已修正。

修复：新增`cycle_clock.h`，保留TIM2为144MHz、32位独立自由计数器，编码器调度、超时、运行时间统计及RGB延时都迁移到TIM2。重复初始化不会重置正在运行的TIM2；差值用无符号32位减法处理约29.83s回绕。当前APB1 /1、TIM2没有其它用途；更改时钟或复用TIM2时须同步调整此实现。

[最终固件回归](fault_results/20261009_134459_swd.json)：DWT在941289219保持不变期间，TIM2从3221663424推进到3237327023，SysTick从201307推进到201418，编码器从392619推进到392831。MOE=0，无HardFault。此处fault=512是先前故意停止心跳的测试结果，随后已记录并清除。

更进一步，[最终运行中DAP回归](current_loop_results/20261009_134455_final_timer_debug_watchdog.json)：2rad/s低速运行时通过SWD读取，MCU一直RUNNING、MOE有效；连接与断开后USB、换相持续正常。随后停止主机心跳，在约0.656s后观察到通信故障0x0200且进入IDLE，MOE关闭。该时间从主机停止发送计起，最后一次心跳早于这个时刻，因此不应把它等同于固件设定的750ms精确测量。

## 其它已处理的控制与测量问题

1. 原电流PI积分没有与最终可实现电压一致的抗饱和，SPWM圆形限幅也超过真实线性输出能力。所有模式现在先限制电压矢量，再反算积分器，避免长期饱和积累。离线真实ARM C函数测试和实机电压饱和测试均通过。
2. 顺序三路ADC转换约2.13µs；原PWM顶点边沿间距仅0.278µs，可落入转换序列。当前固定480/1320边界，各留3.33µs，矢量上限约5.38V@23.07V。网表确认是inline分流器，问题在开关共模瞬态与采样时刻，而不是低侧分流器丢失导通窗口。[INA240手册](https://www.ti.com/lit/ds/symlink/ina240.pdf)不能替代板级模拟恢复时间测量。这个固定窗口明显损失母线利用率，是当前保守验证设计，不能宣称已完成全调制采样设计。
3. 编码器原始角差分速度含噪，更新时刻和角度发布也可能不一致。新增按每次新SSC读数更新的角度/速度观察器，并将角度、速度、位置与时间戳短暂原子发布。读取时间戳靠近寄存器采集，不使用整个处理结束时刻。
4. 通过只读MOD1/MOD2获得实际芯片配置0x4001/0x0801：FIR1、预测关闭，对应数据手册的典型85µs SSC角度时延。Park按电流调理延迟约50µs对齐，逆Park按PWM作用延迟37.5µs预测，均叠加数据年龄和芯片时延。85µs是[Infineon TLE5012B数据手册](https://www.infineon.com/dgdl/Infineon-TLE5012B_Exxxx-DataSheet-v02_01-EN.pdf?fileId=db3a304334fac4c601350f31c43c433f)给出的典型值，并非用此电机辨识出的精确延迟；瞬时加速度和装配误差仍会影响结果。
5. 在真正运行用的注入ADC路径上完成启动零点：先丢弃8帧，再平均400帧，未完成前拒绝启动。普通ADC路径零点只用于初始值，减少两种采样路径偏差。
6. Clarke使用全部三相：α=(2Ia−Ib−Ic)/3，β=(Ib−Ic)/√3，消除传感器共同的零序误差。原始三相、三相和及原始过流保护均保留；不会把真正原始过流通过投影或滤波隐藏。
7. 中值3点和EMA(0.5)保留，剔除逻辑在原始保护之后运行。没有再叠加重滤波把波形强行变平。正常测试中未再出现>6.45A原始峰值统计增加；校准本身仍有短时约6.7A峰值，不能混同于1A运行。
8. 完整校准成功后根据本次R/L计算电流PI：Kp=L×1500、Ki=R×1500，设计带宽约239Hz。这是整定目标，不是闭环实测带宽；L仍有脉冲测量误差，因此不能据此继续大幅加带宽。未写死R、L、极对数或偏置。先用RAM Kp=0.2/Ki=150对比，最终自动参数再单独验收。

最终正反1A各保持1s均无过流：本次最高轴速约80.86/80.97rad/s；遥测原始相电流峰值约1.238/1.147A；Id最大幅值0.579/0.718A，d/q最大幅值1.208/1.197A。当前可用电压约5.4V，达到上限后Iq降到约0.4A，转速约80rad/s。**这验证电流有界和饱和行为，不能称1A持续扭矩仍被准确保持。** 空载恒定Iq本来会加速，随后反电势要求超过可用电压；抗饱和不能突破物理电压上限。此现象已和原先巨大d/q、原始37A记录区分。

最终固件记录ISR最大2828个144MHz时钟≈19.64µs，小于40kHz的25µs预算；ADC异常0。中间版本包含校准的最大3069≈21.31µs。USB抽样和峰值统计不能代替示波器检查所有PWM瞬态。最后补充[±16rad/s的1000Hz波形](current_loop_results/20261009_135127_phase_waveform_1000hz.json)，完成后再次确认空闲、零指令、100Hz，ISR最大仍2828、ADC异常0。80rad/s×21极对对应约267Hz电气基频；500Hz遥测低于其奈奎斯特要求，会产生混叠，因此另保留带混叠提示的80rad/s原始图，而主要相电流图使用16rad/s/1000Hz记录。

## 上位机与保存数据

校准结果在R/L、角度参数与实际Kp/Ki都回读后显示，不会提前报告整定完成。空闲d/q原来是固件历史最后值，GUI现在在空闲段断开d/q曲线，避免把历史电流画成当前电流；原始记录保留历史值，须按state分析。矢量页同步采用三相Clarke。

新增0x08控制诊断帧，与原始相电流、普通遥测按同一seq配对；只有seq匹配且float有限才使用。包括目标d/q、电压d/q、Park/PWM角、观察器角、原始速度、角度年龄、可用电压、原始三相和、芯片延迟。支持空闲设置100/500/1000Hz，测试用500Hz，结束恢复100Hz；没有将不同序号的诊断混成一个时刻。
